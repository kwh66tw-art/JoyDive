# JD2-Logbook 現實規劃版本
## 1 人 PM + Claude Code 模式

**規劃日期**: 2026 年 5 月 17 日  
**現實情景**: 無工程師團隊，1 人 PM（無經驗），完全使用 Claude Code  
**重新評估結論**: ⚠️ **原 18 週計劃不可行，需調整為 24-26 週或縮小範圍**

---

## 第一部分：現實評估

### A. 可用人力分析

**PM 時間投入**：
```
假設 PM 工作時間：每週 40-45 小時（全職）
18 週總投入：720-810 小時
原計劃需求：813-881 小時
─────────────────────────
結論：PM 時間基本足夠，但無餘裕應對突發狀況
```

**Claude Code 的角色**：
```
✅ 可以自動化的工作：
├─ 代碼生成與重構（40-50% 時間節省）
├─ 測試用例編寫
├─ 文檔與註釋生成
├─ 命令行編譯與簡單驗證
├─ Bug 診斷與代碼審查建議
└─ 重複性工作的模板化

❌ 無法完成的工作：
├─ 實際的 Xcode IDE 開發（無 GUI 訪問）
├─ 真實設備上的 UI 測試（無實機）
├─ 程式簽署與 App Store 操作（需帳號操作）
├─ 架構決策（需領域知識）
├─ 使用者體驗驗證（需實機測試）
└─ 最終 bug 修復責任（需人類判斷）
```

### B. 時程現實評估

**原計劃**（18 週，3 人）：
```
Week 1-2:  基礎 (30h)
Week 3-6:  核心解析器 (180h)
Week 7-8:  擴展解析器 (182h)
Week 9-10: 日誌 + GPS (168h)
Week 11-12: 廣告 + IAP (96h)
Week 13-17: 測試 + 優化 (225h)
─────────────────────────────
總計: 881h ÷ 3 人 ÷ 18 週 = 16.3 h/人/週 ✅ 可行

但現在變成：881h ÷ 1 人 ÷ 18 週 = 49 h/人/週 ❌ 不可行（超工時）
```

**時程選項**：

| 選項 | 周期 | PM 周工時 | 可行性 | 說明 |
|------|------|---------|--------|------|
| **選項 A：縮小範圍** | 18 週 | 40-45 h/週 | ✅ 最現實 | 移除部分 P2 功能，v1.0 聚焦 5 種格式 |
| **選項 B：延期上線** | 24 週 | 36-38 h/週 | ✅ 安全 | 全功能 7 種格式，October 2026 → December 2026 |
| **選項 C：極限工時** | 18 週 | 49+ h/週 | ❌ 風險高 | 需要 PM 全職 + 加班，high burnout 風險 |

**建議**：採用**選項 B（延期至 24 週）**
- 理由：完整功能、質量可控、PM 不過勞
- 上線時間：2026 年 12 月中旬（冬季購物季）
- 仍然可趕上傳統淡旺季變化

## 第四部分：PM + Claude Code 協作模式

### 協作流程

```
每個 2 小時工作單位的標準流程：

【PM 準備】 (0.5h)
├─ 了解工作目標與接收標準
├─ 準備必要的環境、測試檔案、參考資料
└─ 與 Claude 溝通具體需求

【Claude 執行】 (1.0-1.5h)
├─ 理解需求、研究最佳實踐
├─ 生成代碼或文檔
├─ 執行編譯、簡單驗證
└─ 返回可運行的產物 (代碼、測試、文檔)

【PM 驗證】 (0.5h)
├─ 在 Xcode 中測試代碼
├─ 驗證功能完整性
├─ 提出修改意見或 approve
└─ Git commit

【迭代】（若需要）
└─ Claude 根據反饋調整 → PM 重新驗證
```

### 工作分配原則

**Claude 負責** (60-70% 工作量)：
- ✅ 代碼初稿生成
- ✅ 測試用例編寫
- ✅ 文檔與註釋
- ✅ 重構與最佳化建議
- ✅ 編譯與簡單驗證
- ✅ Bug 診斷幫助

**PM 負責** (30-40% 工作量)：
- ✅ 架構決策與設計評審
- ✅ 實機測試（Xcode）
- ✅ UI/UX 驗證
- ✅ Git 管理與版本控制
- ✅ App Store 操作
- ✅ 最終功能驗證
- ✅ 風險決策與調整
