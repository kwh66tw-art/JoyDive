## 一、範圍

水面氣壓為 0、負數、NaN 或超出合理範圍時，**重放面**已由 DiveKit v9.8.0 處理（F14：數值不合理 ⇒ `Anomaly.implausibleEnvironment` 拒算；
branch 79e56d9，合併後總指揮通知）。D-C 只剩 **App-lb 顯示層**：「高海拔」徽章，以及詳細頁／地圖面板的環境列。

## 二、App-lb 現況

- `DiveLog.isHighAltitude` ＝ `surfacePressureBar < 0.95`（`JD2Core/Models/DiveLog.swift:370`；門檻 `:367`，本專案決定，比照 App-u 手錶）。
  唯一使用處：`DiveLog+EnvironmentDisplay.swift:23`（詳細頁與地圖面板共用）。
- 0、負數 ⇒ 顯示「高海拔」徽章；NaN ⇒ 不顯示（比較恆 false）。測試鎖現況：`EnvironmentEdgeCaseTests.testImplausibleSurfacePressureCurrentBehavior`。
- 推導不寫回資料（裁示 (b)）。

## 三、這類值從哪裡來（App-lb 讀碼）

| 來源 | 會不會產生 |
|---|---|
| 新匯入 | DiveImportKit v0.8.2 起各解析器都經 `SurfacePressureParsing`（0.5–1.2 bar），不合理 ⇒ nil ⇒ App 存預設 1.0 |
| **既有使用者資料** | **會**：v1.0–v1.3 以 DiveImportKit v0.8.2 前的 Subsurface XML 匯入的 0 bar／nan 已在使用者資料庫中；v0.8.2 只擋新匯入 |
| 手動新增／編輯頁 | 不會（無水面氣壓欄位） |
| 備份還原 | 手改或外部產生的 JSON 可帶 0／負數；NaN 不行（JSONDecoder 預設拒絕） |

⇒ 存量資料真實存在，顯示層需要決定。

## 四、家族範圍不一致：刻意分開（總指揮讀碼）

- DiveImportKit 0.5–1.2：**抓單位 bug 的窗**（`SurfacePressureParsing.swift` 檔頭寫明「抓 bug 的下限、不是生理門檻」，與 App 層 `minPlausibleAbsolutePressureBar` 同值）。
- DiveKit 0.60–1.10（`DiveEnvironment.plausibleSurfacePressureRangeBar`，`DiveEnvironment.swift:82`）：重放與手錶開潛的可信範圍。
- 🔑 **不能把 DIK 收窄到 0.60–1.10**：DIK 回 nil 時 App-lb 存預設 1.0，重放會當可信照算；保留原值則 Kit v9.8.0 判不合理拒算 ⇒ **匯入寬、計算嚴**才是保守方向。
- 可達性：真實語料 94 處水面氣壓皆在 0.896–1.046 bar，兩窗之間的中間地帶無樣本。

## 五、選項

| 選項 | 作法 | 評估 |
|---|---|---|
| **(a)（聯合推薦）** | 只有在 Kit 合理範圍內且 < 0.95 才顯示徽章：`DiveEnvironment.plausibleSurfacePressureRangeBar.contains(p) && p < 0.95`；範圍外（0、負數、NaN、>1.10）不顯示徽章，環境列只顯示水域 | 一個值一個來源：徽章、重放、手錶開潛三處用同一把尺，不會出現「顯示高海拔、重放卻說環境不合理」的矛盾；不另寫 App 常數（D4）；0.95 仍是本專案決定 |
| (b) | 範圍外改顯示「水面氣壓異常」提示 | 要新增文案與 18 語翻譯；v9.8.0 重放拒算時已有說明，不需要 |
| (c) | 維持現況 | 0 bar 顯示「高海拔」，是錯誤資料造成的誤導 |

三案皆**不改寫存量資料**。

## 六、跨 App

### 六之一（總指揮讀碼）

- App-u／App-i 手錶：記錄時就把水域字串寫死（App-u `DiveLogRecorder.swift:280-281`、App-i `DiveLogRecorder.swift:232-233`：有實測值時 `< 0.95` 寫 "altitude"，否則依檔位）；實測值開潛前已用 0.60–1.10 擋過（App-u `AppModel.swift:123-126`）。
- App-u 手機環境列吃存下來的 `environmentType` 字串（`DiveLogDetailView.swift:41-46`、`DiveSiteSheetView.swift:43-45`），**不從氣壓推導、沒有徽章**。
- ⇒ App-u 手機拿掉「≤0／NaN 換成 1.0」只影響重放（改由 Kit 拒算），不影響顯示；App-u 本來也不產生這類值（無匯入、手錶有擋）。
- 與 App-lb 的差別：App-lb 從氣壓推導（裁示 (b)），App-u／App-i 存字串；門檻同為 0.95 ⇒ 同一個實測值兩邊結論相同。
