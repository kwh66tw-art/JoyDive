## 三、F-09 實驗：「+%lld more」能不能依數量變形（PM 11/04 同意；總指揮設計）

**問題**：F-09（2026-07-28）Logbook 段的結論是「`languageManager.localized()` 走 `Bundle.localizedString(forKey:)`，會略過 plural variations」。總指揮推論：可能不成立，可能只差格式化的寫法。

**做法**（App-lb 11/04，iOS 模擬器單元測試；**實驗字串與測試皆未提交**）：
- 只動「+%lld more」一個鍵，加 Vary by Plural：en `one`「+%lld EN-ONE」／`other`「+%lld EN-OTHER」；hr `one`「+%lld A」／`few`「+%lld B」／`other`「+%lld C」（測試用字串）。
- 暫時測試類別：`AppLanguageManager.appLanguage = "hr"`（再測 `"en"`），呼叫**真正的** `languageManager.localized("+%lld more")`，數量 1、2、5、21，三種寫法各格式化一次。
- `run_tests.sh logbook --only TempF09PluralExperimentTests`：`RESULT|PASS|passed=1|failed=0|skipped=0`。第一輪 `print` 沒進 xcresult、無法判讀；第二輪改寫檔案，可判讀（兩輪內）。
- 收尾：`Localizable.xcstrings` 由備份還原，SHA-256 `3a0685f3…651a5` 與實驗前相同；暫時測試檔已刪。

**結果**：

| 語言 | 數量 | 預期（CLDR） | `String(format:)` | `String.localizedStringWithFormat` | `String(format:locale:)` |
|---|---|---|---|---|---|
| hr | 1 | one → A | +1 C | +1 C | **+1 A** ✅ |
| hr | 2 | few → B | +2 C | +2 C | **+2 B** ✅ |
| hr | 5 | other → C | +5 C | +5 C | **+5 C** ✅ |
| hr | 21 | one → A | +21 C | +21 C | **+21 A** ✅ |
| en | 1 | one | +1 EN-OTHER | +1 EN-OTHER | **+1 EN-ONE** ✅ |
| en | 2／5／21 | other | EN-OTHER | EN-OTHER | **EN-OTHER** ✅ |

- `localized()` 回傳的格式字串是 `%#@value@`，底層型別 `__NSLocalizedString`：**plural 資料有經過 `Bundle.localizedString(forKey:)` 傳下來**，F-09「這條路徑會略過 plural variations」的結論**不成立**。
- 會不會選對，取決於格式化時給的 locale：只有 `String(format:locale:)` 帶 `languageManager.locale` 時依語言規則選詞形；另兩種寫法在本實驗一律落到 `other`（為什麼是 `other` 未追查，也與本案無關）。
- **Logbook 的「+%lld more」現在就是 `String(format: othersFormat, locale: locale, …)`**（`DiveMapRepresentable.swift:72`，`locale`＝`languageManager.locale`，`:301`）⇒ 上架前要依數量變形，**只需在 xcstrings 加 Vary by Plural、不必改程式碼**。
- ⚠️ 未驗證：模擬器地圖上實際顯示（要做出 2／3／6／22 筆的聚合點）；本實驗走的是同一個 `localized()`＋同一種格式化呼叫，但不是畫面截圖。
- 範圍：只驗了這一個鍵、hr／en 兩語、`%lld` 一個參數。其他用 `String(format:)`（不帶 locale）的呼叫點，若要變形需改成帶 locale。
